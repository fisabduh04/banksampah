# Services

## Historical corrections must not replay transaction posting
Do not repair historical journals by rerunning transaction post services: balance and inventory ledgers may already exist. For each verified historical balance and cut-off, choose either event reconstruction or opening balances, with explicit covered references; never both for the same economic amount. Trial data and agreement with GL do not establish approved real opening balances.

## Cleanup metadata equivalence must not weaken snapshot checks
Compare every FK; NO ACTION and RESTRICT are equivalent only after validating InnoDB. Legacy format-1 manifests omitted the engine but were generated by an InnoDB-only collector. Limit CURRENT_TIMESTAMP/DEFAULT_GENERATED equivalence to failed_jobs.failed_at with all other attributes identical. Never normalize away cache, sessions, master or transaction content changes. @@transaction_isolation/@@tx_isolation report session defaults, not one-shot transaction overrides: establish REPEATABLE READ explicitly for each owned transaction and reject nested transactions; never change global isolation.

## Readable document numbers use separate idempotency keys
ST, WD, and PJ numbers use independent yearly sequences locked in document_number_sequences. Preserve the locked form token as idempotency_key; never use count()+1 or an ULID as the displayed number. Historical ULID renumbering must atomically update source references, retain old/new numbers in document_number_changes, and never replay posting or alter financial amounts.
